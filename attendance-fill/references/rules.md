# 填写规则与确认数据

## 模板定位

读取工作表的人员姓名行，姓名旁的“当日总工时”列构成一组。日期与星期各占三行合并区块，时段依次填写上午、下午、晚上，日工时写入对应合并区域左上角。期间合计写入本人“合计总工时”区域左上角。

人员以当期模板为准，列位置通过姓名匹配取得。日期按 Excel 日期系统解释并与星期核对。使用合并区块和标签定位合计位置。

## 默认常规规则

| 分类 | 上午 | 下午 | 晚上 | 基准工时 |
| --- | --- | --- | --- | --- |
| 工作日 | 9:00–11:00 | 12:00–17:00 | 19:00–21:00 | 9h |
| 周六出勤 | 9:00–11:00 | 14:00–17:00 | 19:00–21:00 | 7h |
| 周日出勤 | 9:00–11:00 | 14:00–17:00 | 19:00–22:00 | 8h |

这些基准取自使用者最初提供的已填样例中的主要模式。默认出差地点为样例中的“嘉兴”，使用者提供的本期地点或明确修改的个人默认地点优先。

周末、出差确认出勤后，使用当天星期对应的常规规则。确认休息的日期三个时段填写“休息”，日工时为 `0h`。其他例外可指定状态或三个具体时段。

出差日期的三个时段按常规显示，地点标识写在当日总工时栏。例如生成 9 小时时显示 `嘉兴9h`。工时以分钟精确求和，显示为最多两位小数的小时数并附 `h`。期间合计从所有日期的分钟总数计算。

## 重复与变化

按工作日、周六、周日分别选择变化日期。每类约 70% 日期复用基准，约 30% 日期变化。类别至少含三个出勤日期时，至少保留两个基准日期并选择至少一个变化日期。类别含一至两个日期时直接按可用规则生成。

变化日期随机调整一至两段，每段的起止时刻分别在基准前后 1.5 小时内按 30 分钟步长变化。每个选中的时段应实际发生变化，结束时间晚于开始时间，各段之间保持至少一个 30 分钟步长的休息间隔。日工时随生成的时间差计算。

保存每期的日期、时段、计算结果和规则信息。重复运行及补充例外时优先复用已生成日期的结果，受影响日期单独更新。若原变化日改为休息后，同类至少三个自动出勤日全部相同，则最少调整一个自动日期恢复变化。若基准重复日不足两个，则以最少调整恢复重复。明确指定时段的例外采用使用者原值。计划摘要记录额外调整日期。`--regenerate` 用于使用者明确要求重抽时段的情形。

## 历史更新

按已保存姓名读取上传历史，提取完整日期、三段时段、日工时和出差地点。工作日、周六、周日分别统计整日三段组合的出现次数。排除出差日、缺失记录、含休息或其他状态的日期，以及手填工时与时段复算冲突的日期。

各分类采用最常见的组合。出现并列时优先采用当前已保存的组合，其余情形取最近出现的组合。没有足够可用记录的分类沿用现有规则。出差地点采用有效出差记录中最常见的地点。输出提取结果、来源日期和冲突，更新个人规则。

历史中的手填工时用于核对，起止时间的分钟差用于计算。样例中曾出现时段合计 12 小时、手填 11h 的记录，该记录作为冲突报告并排除常规学习。

## 确认文件

使用者通过自然语言答复，代理负责将结果展开到各日期并整理为脚本所需 JSON。以下为结构示例。

```json
{
  "weekends": {
    "2026-10-31": true,
    "2026-11-01": false,
    "2026-11-07": true,
    "2026-11-08": true,
    "2026-11-14": false,
    "2026-11-15": false
  },
  "trips": [
    {
      "date": "2026-11-02",
      "attend": true,
      "location": "嘉兴"
    }
  ],
  "exceptions": [
    {
      "date": "2026-11-03",
      "status": "事"
    },
    {
      "date": "2026-11-04",
      "periods": ["9:00-11:00", "14:00-17:00", "休息"]
    }
  ],
  "other_exceptions_confirmed": true
}
```

`weekends` 包含模板周期内所有周六、周日，每个日期的布尔值代表出勤选择。批量答复先展开为逐日值。

`trips` 包含本期已说明的出差日期，每个日期需有 `attend`。`location` 优先采用本期信息，缺省时采用已保存默认地点。空数组表示使用者确认本期无出差。

`exceptions` 包含其他例外。`status` 可填写 `休息`、`事`、`病`、`缺`，或使用三个元素的 `periods` 表达临时作息。明确的逐日例外优先于本期通用规则，出差信息负责总工时的地点格式。重复或矛盾的逐日指令应先明确。

`other_exceptions_confirmed` 为 `true` 表示本期其他例外已确认。计划命令返回待确认项时，按返回内容补齐，随后继续生成。

个人姓名和长期规则写入个人配置，周末、出差和其他例外写入当期确认文件，随机时段写入当期状态文件。确认数据及生成结果仅用于其所属周期。

## 保存后验证

`verify` 逐项核对写入值、分钟数和合计，并比较原表的其他内容、公式、合并、行列尺寸和可见样式。失败时根据具体差异修正后重新导出，验证通过后交付。

当前导出引擎会归一化旧字体字符集元数据。验证结果的 `metadata_changes` 会记录此项，同时独立检查字体名称、字号、颜色和其余可见属性。版式仍需通过填写前后预览核验。
